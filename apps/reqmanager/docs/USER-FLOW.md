## UF-01 需求生命週期（跨角色泳道）

```
狀態：草稿 → 待評估 ⇄ 待補件 → 待排程 → 開發中 ⇄ 待測試 → 待業務驗收 → 已結案
                  ↘ 不採納          ↘ 已取消（PM，需決策者同意）      ↖ 重新開啟（回待評估）
```

| 階段 | 業務 | PM | 工程 | QA |
|---|---|---|---|---|
| Submit 提交 | 建客戶、記互動、**填表提交** | 收提交通知 | | |
| Evaluate 評估 | 收補件通知 → **補充資訊** | **接受／要求補件／不採納** | 技術評估、估工 | |
| Assign 指派 | 收接受通知 | **指派開發、承諾日期、驗收條件** | 收指派通知 | |
| Track 開發 | 隨時查進度 | 變更承諾日期（必填原因） | **開發、提交測試版本** | |
| Test 測試 | | 監督 | 測試失敗 → 修正 | **逐案記錄結果、缺陷** |
| UAT 業務驗收 | **逐項確認：通過／退回** | 收 UAT 通過通知 | 驗收退回 → 修正 | |
| Close 結案 | 收結案通知 | **確認三項檢查後結案** | | |

合法轉換與觸發者完全依 PRD 7.2，規則寫在 `src/domain/rules.ts`（`ACTIONS`），前端與後端共用。

## UF-02 各角色畫面流程

- **業務**：S01 登入 → S02 工作台（待我補件／待我驗收／我提交・處理中／即將逾期）→ S03 客戶 → S04 記互動 → S06 提交需求 → S07 查進度／補充資訊 → S09-B 業務驗收
- **PM**：S01 → S02（待評估／待排程／待結案／逾期）→ S07 → S08-A 接受／補件／不採納 → S08-B 開始開發 → S09-C 結案 → S10 報表
- **工程**：S01 → S02（開發中／退回待修正／即將逾期）→ S07（只看被指派）→ 提交測試版本
- **QA**：S01 → S02（待測試）→ S07 → S09-A 記錄測試結果
- **Admin**：S01 → S11 帳號與權限 → S12 系統狀態（資料管理）

## UI 共通規則（PRD 10.1）落實方式

- 狀態一律「文字＋顏色」標籤（`StatusChip`）。
- 表單錯誤就地提示於欄位下方，並在表單頂端彙總；已輸入內容保留。
- 明確區分三種畫面：無資料（`EmptyState`）、無權限（`NoPermission`，API 403）、讀取失敗（`ErrorState`，可重試）。
- 日期格式 YYYY/MM/DD，時間一律 Asia/Taipei。
- 全部互動元素可用鍵盤操作（原生 button／select／input、Esc 關閉對話框、focus 樣式）。
