# 目的導向簡報（Purposeful Presentation）

好的簡報 ≠ 漂亮的簡報。簡報最基本的工作，是把一件事簡單說明白、讓彼此認知一致，才能提高達成目的的成功率。以下每條規則都在替觀眾排除障礙。

依序執行四個階段；每階段結束前完成該段檢查表。規則細節見同資料夾：
- [`references/charts.md`](references/charts.md) — 圖表、框線、表格的選用與畫法
- [`references/checklist.md`](references/checklist.md) — 交付前逐頁檢查表

---

## 階段 1：動筆前，先想「為什麼要寫」

先回答這五題，寫成一段「簡報簡報」（brief）放在大綱最上方。任何一題答不出來，先問使用者，不要開始做頁面。

| 問題 | 要寫下的答案 |
|---|---|
| **目的** | 這份簡報最終要「獲得認可／解決問題／達成共識／爭取資源／促成面試…」哪一個？一句話。 |
| **一定要簡報嗎？** | 如果找到關鍵 Key man 直接談就能解決，誠實告訴使用者。簡報只是工具之一。 |
| **受眾是誰** | 團隊成員、其他部門、直屬長官、客戶、評審、面試官？ |
| **受眾條件** | ① 專業知識：用對方懂的術語；② 立場：合作、競爭、協商或宣傳；③ 時間：對方給你幾分鐘。 |
| **誰有決定權** | 哪一位能拍板定案？整份簡報主要為他服務：他最在意的事放最前面。 |

再判斷情境：**內部溝通**以達成目的為主，美化點到為止；**外部展示**（客戶、評審、求職）值得投資視覺品質。

## 階段 2：規劃大綱（主次分明）

1. **第一頁破題**：首頁（或封面後第一頁）讓所有人對「今天要處理什麼」有相同認知：議題、為什麼現在、希望得到的決定或結果。破題同時框住討論範圍，避免離題。
2. **一頁只講一件事**；上下頁必須有邏輯關係（因果、遞進、對比、總分）。
3. **換主題就放轉折頁**（章節頁），讓觀眾有心理預期。
4. **主次分明**：每頁明確區分「主訊息」（標題結論＋一個視覺主體）與「次要資訊」（輔助數據、註記）。次要資訊字級、顏色、位置都要讓位。
5. **產品／提案類簡報**用這條主線，依受眾刪減，不要調換順序：

   | 段落 | 回答的問題 | 必備證據 |
   |---|---|---|
   | 使用者需求 | 誰、遇到什麼問題、多痛？ | 可量化數據（比例、次數、成本、時間） |
   | 產品／方案 | 我們怎麼解決？ | 一張流程或架構圖，不寫說明文 |
   | 創新性 | 跟現在的做法比，新在哪？ | 前後對比（長條圖／對照表） |
   | 獨特性 | 為什麼是我們、別人難以複製？ | 比較表（我方 vs 替代方案） |
   | 成果／數據 | 有效嗎？ | 趨勢（折線圖）、占比（圓餅圖）、關鍵數字 |
   | 下一步 | 需要決策者做什麼？ | 明確的請求與時程 |

   作品集／履歷簡報的對應：需求 → 職缺要的能力；產品 → 你的核心技能；創新性 → 你的做法；獨特性 → 你和其他人的差別；成果 → 經歷數據與案例。

## 階段 3：寫每一頁

- **標題放結論或觀點**，不放主題名稱。✗「Q3 營收」→ ✓「Q3 營收成長 18%，主因新客」。觀眾恍神時，看標題就能跟上。
- **內容只留關鍵字**：每頁內文（不含標題、圖表標籤）**不超過 20 字**。字多就拆頁。不要把 Word 文件貼進 PPT：Word 記錄思路，PPT 展現影響力。
- **數據要可量化、可比較**：能用數字就不用形容詞；每個數字附單位、期間與來源。數據一律來自素材，**絕不杜撰**；缺數據就標示「待補」並問使用者。
- **有數據就畫圖**：依 `references/charts.md` 選圓餅、長條、折線或表格；用框線把不同性質的資訊分區。
- **備註只放提示**：備註寫 3–5 個關鍵詞提醒，不寫逐字稿，講者才能看著觀眾講。
- **動畫只用淡入、淡出**，而且只在「逐步推理」時使用（例如先出問題、再出答案）。不用其他轉場。

## 階段 4：視覺規則（投影到大螢幕也看得清楚）

| 項目 | 規則 |
|---|---|
| 最小字 | **≥ 16 pt**（圖表標籤、註腳、頁碼都算） |
| 標題 | **≥ 26 pt** |
| 重點數字／主訊息 | **≥ 40 pt** |
| 字體 | 預設統一用「微軟正黑體」系列（Microsoft JhengHei／JhengHei UI）。若有品牌設計系統，標題可用品牌字，但要確認對方電腦有該字型或已嵌入；內文仍以微軟正黑體為後備。 |
| 配色 | 避免淺色塊配白字、深色塊配黑字、相近飽和度相鄰。文字對比 ≥ 4.5:1（≥ 24 pt 粗體可 3:1）。 |
| 色盲友善 | 需要區分的顏色要「明度」不同，不只色相不同；避免紅綠配對，優先藍／橘；圖表一律直接標數值或標籤，不只靠圖例顏色。 |
| 測試 | 提醒使用者：正式簡報前到會議室投影，從最遠、最偏的座位看一次再調整。 |

## 階段 5：做出來（內建產出工具）

本 skill 自帶一套從參考簡報拆解出的**風格主題＋頁面版型**，可直接產出可編輯的 PPTX（原生文字框、形狀、可改數據的圖表）。拆解分析見 [`references/visual-patterns.md`](references/visual-patterns.md)。

1. **每頁先選「頁面任務」，再選版型**（`type`）：

   | 頁面任務 | 版型 |
   |---|---|
   | 破題 / 結尾請求 | `cover` / `closing` |
   | 預告結構 / 轉折 | `agenda` / `section` |
   | 使用者需求、痛點 | `problem`（`columns` 或 `stack`） |
   | 產品、方案、能力並列 | `cards`（可加 `effects` 虛線效果框） |
   | 方法、步驟 | `process` |
   | 創新性（改變了什麼） | `before_after` |
   | 獨特性 | `venn`（交集）、`table`（比較表） |
   | 成果數字 | `kpi`（`tile` 或 `ring`） |
   | 比較／成長 · 趨勢 · 占比 | `bar` · `line` · `pie` |
   | 利害關係人、價值 | `hub` |
   | 時程、下一步 | `roadmap` |

2. **選一個主題**（`theme`）：`deep_blue`、`friendly`、`infographic_navy`、`eco_green`、`fintech_teal`、`humanizer`。內部溝通選最簡潔的即可；外部展示再挑最貼近品牌的。

3. **寫 JSON 規格**（範例：[`examples/showcase.json`](examples/showcase.json)，涵蓋全部 16 種版型）。標題用 `**…**` 標出結論詞，會自動上主題色；圖表頁一定填 `source`。

4. **產出與檢查**：

   `<SKILL_DIR>` 是這個 skill 資料夾的絕對路徑（SKILL.md 所在處）。需要 `python-pptx`，沒有就先 `pip install python-pptx`。

   ```bash
   python3 <SKILL_DIR>/scripts/deck.py spec.json out.pptx
   python3 <SKILL_DIR>/scripts/deck.py --list   # 列出主題與版型欄位
   ```

   產出的 `.pptx` 存到使用者可下載的輸出位置（例如 `/mnt/user-data/outputs/`），並附上連結。

   程式會強制字級下限（16／20／30／44 pt）、只用淡入轉場、圖表只亮一個重點，並輸出 `[LINT]`：對比不足、內文過長、標題超過 28 字、圓餅超過 5 塊、折線超過 4 條、表格超過 5×6、圖表缺來源。**每條 LINT 都要處理或向使用者說明。**

5. **目視檢查**：`soffice --headless --convert-to pdf out.pptx` 後轉圖檢查文字是否溢出。預覽範例見 `examples/previews/`。

## 搭配其他簡報工具

內建產生器是預設做法。若環境中另有簡報工具（例如 ppt-master、guizang-ppt-skill、pptx skill）且使用者指定使用，本 skill 仍負責階段 1–4：把 brief 與大綱交給該工具，字級下限照階段 4。網頁簡報把 pt 換算為 px（16 pt ≈ 21 px @ 1920 寬）。

## 交付前

逐頁跑 [`references/checklist.md`](references/checklist.md)。回報時列出：未通過且刻意保留的項目（例如來源本身的低對比顏色）與原因、仍「待補」的數據。
